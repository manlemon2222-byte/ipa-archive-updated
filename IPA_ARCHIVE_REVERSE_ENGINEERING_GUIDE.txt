1. EXECUTIVE SUMMARY & SYSTEM SCALE
--------------------------------------------------------------------------------
The Grand IPA Archive is a decentralized, zero-storage indexing engine and 
Over-The-Air (OTA) distribution platform for historic iOS applications (.ipa).

Instead of downloading petabytes of IPAs from Archive.org, the crawler performs 
selective HTTP Range queries over the network, extracting only the metadata 
(Info.plist) and app icons (~60 KB per app), converting Apple's proprietary 
graphics formats, deduplicating assets, and publishing a lightweight static web

2. HOW main.py PROCESSES ZIP AND RAR ARCHIVES
--------------------------------------------------------------------------------
The core technical challenge: Archive.org frequently packages hundreds of .ipa 
files inside multi-gigabyte (10GB–50GB+) .zip, .rar, .7z, or .tar files. 
main.py completely avoids downloading these containers through a two-phase 
architecture:

A. DISCOVERY / PEEKING PHASE (Zero Full Downloads)
   When crawling a collection via `main.py add <URL>`:
   
   1. For .ZIP Containers (getNestedIpas):
      - A standard ZIP file stores its directory index (Central Directory) at 
        the very END of the file archive.
      - The script uses Python's `RemoteZip` library, sending HTTP Range requests:
        `Range: bytes=-65536` to fetch only the final 64 KB of the remote archive.
      - It parses the Central Directory structure in memory, listing every nested
        .ipa path and uncompressed size in 1-2 seconds without pulling file payloads.
   
   2. For .RAR / .7Z / .TAR Containers (getNestedIpasViaViewArchive):
      - Non-ZIP formats (RAR, 7z) place their file tables throughout or compress 
        their headers, making direct HTTP Range reading unfeasible.
      - main.py circumvents this by querying Archive.org's server-side inspection
        bridge (`view_archive.php`):
        `https://archive.org/download/{archiveId}/{archive_name}/`
      - Archive.org dynamically renders an HTML table of all nested files.
      - main.py parses this table with high-speed regular expressions:
        `pattern = r'<tr><td><a [^>]*href="[^"]*">([^<]+)</a><td><td>[^<]*<td [^>]*size">(\d+)</tr>'`
      - It discovers all nested .ipa files without transferring the archive container.

   3. Internal Naming Format (The "##" Separator):
      - Discovered nested items are stored in SQLite using `##` (NESTED_SEP):
        `BigCollection.zip##Games/Action/Doom.ipa`
        `RetroPack.rar##Apps/Calculator.ipa`
      - When exporting or linking, `##` is seamlessly converted into URL slashes.

B. TARGETED EXTRACTION PHASE (loadIpa)
   When indexing pending items via `main.py run`:

   1. If the container is RAR / 7z / tar:
      - Archive.org's bridge allows downloading individual files from inside an 
        archive via direct URL:
        `https://archive.org/download/<collection>/<archive.rar>/<path/to/inner.ipa>`
      - main.py streams only that specific .ipa into a local temporary file
        (`tempfile.NamedTemporaryFile`).
      - It hands the temp file to `_processIpaZip()` and deletes it immediately after.

   2. If the container is a nested ZIP:
      - `RemoteZip` opens the outer ZIP on Archive.org.
      - It streams only the inner .ipa bytes out of the outer ZIP into a temp file.
      - It hands the temp file to `_processIpaZip()` and unlinks it.

   3. If the item is a direct standalone .ipa (Optimal Path):
      - Because an .ipa file is internally a standard ZIP file, `RemoteZip` 
        connects directly to the remote .ipa on Archive.org.
      - It streams ONLY the specific byte ranges for `Payload/*.app/Info.plist`
        and the matching icon PNG.
      - For a 2 GB application, only ~60 KB of data is transferred over the network!

3. THE INSIDE-IPA PIPELINE (_processIpaZip)
--------------------------------------------------------------------------------
Once a zip handle to the .ipa is established:

1. Law of Fresh Extraction:
   - Stale metadata, plists, or partial thumbnails from previous runs are deleted 
     first to eliminate "sticky corruption".

2. Info.plist Extraction & WeChat Sanitization:
   - Locates `Payload/*.app/Info.plist`.
   - `remove_wechat_app_ids()`: Scans the plist bytes for leaked WeChat URL schemes 
     (`wx[0-9a-f]{16}`) and strips them from both XML and binary plist structures.
   - Fallback Plist Parser: If binary plist parsing fails due to syntax errors, 
     a fallback regex parser extracts keys directly.
   - Fallback Bundle ID Inference: If the plist has a dummy ID (e.g., 
     'iphone.app.mega.pack'), regex `RE_BID` infers the true bundle ID from the filename.
   - Title Polisher (`prettify_title`): Strips build strings, CamelCase-splits words,
     and cleans version noise.

3. App Icon Extraction:
   - Resolves icons in order of authenticity:
     `CFBundleIcons` -> `CFBundleIcons~ipad` -> `CFBundleIconFiles` -> 
     `CFBundleIconFile` -> `iTunesArtwork` -> Folder PNG fallback.

4. Proprietary CgBI De-normalization:
   - Apple optimizes PNGs using a non-standard `CgBI` header with premultiplied BGR
     byte ordering and deflated zlib blocks.
   - Standard image libraries (like PIL) cannot decode raw CgBI PNGs.
   - main.py calls `./pngdefry/pngdefry -s -free <icon.png>` to reverse Apple's 
     optimizations into standard RFC-compliant PNG files.

5. Image Optimization:
   - PIL converts the PNG into an RGB JPEG thumbnail (maximum 128x128 pixels, 
     quality 80, optimize=True).
   - Sets file permissions to 0644 and deletes the temporary PNG file.

6. Image Copy Detection (ICD) 3-Stage Pipeline:
   To prevent catalog pollution by generic placeholder artwork (e.g. coconut dummy,
   GamesRoom dummy):
   - Stage 1 (Exact Hash): Matches file MD5 against `KNOWN_BAD_ARTWORK_MD5`.
   - Stage 2 (Global Perceptual Hash): Calculates visual 64-bit difference hash 
     (`calc_dhash`) and computes Hamming distance (dist <= 4 or <= 8).
   - Stage 3 (Lite-D2LV Spatial Grid): Extracts a 4x4 micro-fingerprint spatial grid 
     (`extract_spatial_grid`) to verify candidate matches and reject false positives.

7. Cross-Version Icon Deduplication:
   - If another version of the app with the same Bundle ID already has an icon, 
     the database reuses `image_pk` and deletes the newly downloaded icon to save space.

4. DATABASE & SHARDED STORAGE ARCHITECTURE
--------------------------------------------------------------------------------
A. SQLite Database (`data/ipa_cache.db`):
   - WAL Mode Enabled: `PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL;`
   - Memory Optimization: `PRAGMA mmap_size=268435456; PRAGMA cache_size=-64000;`
   - Core Tables:
     * `urls`: Base Archive.org collection URLs (`pk`, `url`, `date`).
     * `idx`: Master index of all .ipa files (`pk`, `base_url`, `path_name`, `done`,
       `fsize`, `min_os`, `platform`, `title`, `bundle_id`, `version`, `image_pk`).
     * `scrape_queue`: Queue for crawling collections with resume support.
     * `scanned_archives`: Tracks completed archive scans (avoids re-scanning).

B. State Engine (`done` column in `idx`):
   - `0`: Queued / Pending processing
   - `1`: Successfully indexed
   - `2`: Processed successfully, but icon is missing / queued for retry
   - `3`: Temporary error (timeout, 503, retryable)
   - `4`: Permanent error (corrupted zip, 404, ignored in export)

C. Filesystem Sharding:
   - Putting 200,000+ files in a single folder causes Linux/Android inode bottlenecks.
   - Files are sharded by `uid // 1000`:
     Metadata: `data/{uid // 1000}/{uid}.plist`
     Artwork:  `data/{uid // 1000}/{uid}.jpg`

5. FRONTEND & OVER-THE-AIR (OTA) INSTALLATION
--------------------------------------------------------------------------------
A. Static Web Catalog (index.html + script.js):
   - Runs client-side on GitHub Pages, written in ES3/ES5 for backwards compatibility
     with legacy Safari (iOS 3, 4, 5, 6+).
   - `data/ipa.json` stores array tuples for minimal bandwidth:
     `[pk, platform, minOS, title, bundleId, version, baseUrlId, pathName, size, image_pk]`
   - Supports search, fuzzy whitespace-insensitive matching, bundle clustering, 
     minimum/maximum OS version filters, device bitmasks, and iTunes Store enrichment.

B. The OTA Plist Server (tools/plist_server.py / PHP):
   - iOS cannot install raw .ipa files directly through mobile Safari.
   - Apple requires the wireless Enterprise / Ad-Hoc distribution protocol:
     `itms-services://?action=download-manifest&url=<plist_server>?d=<base64_json>`
   - The Plist Server dynamically renders a valid Apple XML deployment manifest:
     * `software-package` -> Direct Archive.org .ipa URL
     * `display-image`    -> Cached .jpg icon URL
     * `bundle-identifier` & `bundle-version` -> Real app parameters

6. CLI COMMAND REFERENCE CHEAT SHEET
--------------------------------------------------------------------------------
Add and Crawl:
  python3 main.py add "https://archive.org/download/<id>"   # Add new collection
  python3 main.py add continue                              # Resume interrupted scrape

Process and Index:
  python3 main.py run                                       # Run 10-thread extraction
  python3 main.py run -retry                                # Automatically retry failed
  python3 main.py run -force                                # Re-index all entries

Maintenance and Repairs:
  python3 main.py fix-imgs                                  # Detect and fix missing icons
  python3 main.py err reset                                 # Reset temporary errors (done=3 -> 0)
  python3 main.py err fix                                   # Loop and repair retryable errors
  python3 main.py err clear                                 # Delete done=3 and done=4 entries

Export for Web:
  python3 main.py export json                               # Generate data/ipa.json & urls.json

Launch OTA Server:
  python3 tools/plist_server.py                             # Start local plist server on port 8026
